# Дорожная карта

Порядок работ по `docs/design.md`. Веха считается закрытой, только когда выполнен
ее критерий приемки — не когда написан код.

## Как ведется работа

- Один шаг — один коммит, сообщение короткое, на русском, только заголовок.
- Перед каждым коммитом: `gofmt -l .` пусто, `go vet ./...` и `go test ./...`
  зеленые. Коммит с красной проверкой не делается.
- Живые прогоны — в отдельном каталоге `/tmp`, со своим `REWAKE_DIR`. Рабочие
  сессии harness пользователя не трогаются.
- Живые прогоны Codex тратят квоту подписки: дешевая модель, короткие сообщения,
  не больше одного хода на проверку. Перед прогоном, который тратит квоту,
  предупреждать владельца.
- После вех 3 и 5 — заход ревью отдельным агентом по диффу: ищет дефекты и
  проверки, которые зеленеют на сломанном коде. Находки чинятся до следующей вехи.
- Веха с пометкой **живой критерий** принимается запуском настоящих harness, а не
  тестами.

## Веха 1. Скелет и интерфейс

Каркас CLI без доставки: таблица команд, разбор, обзор, справка, отказы.

- `go.mod`, раскладка пакетов из design, `cmd/rewake`.
- `internal/cli`: таблица команд (имя, аргументы, флаги, summary, examples, next,
  notes), разбор аргументов, обзор без аргументов, `--help` по команде,
  оформление отказа (причина, синтаксис, примеры, `full help:`), «did you mean»
  по расстоянию редактирования, коды выхода 0/1/2/3.
- `internal/cli`: печать модели — колонки и `--json` одной функцией.
- Команды пока печатают заглушки.

Тесты: разбор аргументов, неизвестный флаг и лишний позиционный дают код 2,
таблица команд покрыта обработчиками в обе стороны, примеры из таблицы
разбираются без ошибок.

Приемка: `rewake` без аргументов печатает обзор; `rewake send` без аргументов
печатает отказ с синтаксисом и примерами.

## Веха 2. Состояние и реестр

- `internal/state`: каталог `$REWAKE_DIR` или `/tmp/rewake-<uid>`, проверка
  владельца и прав, создание 0700, пути, атомарная запись (tmp + rename).
- `internal/proc`: время старта процесса из `/proc/<pid>/stat`, дерево процессов,
  ссылки `/proc/<pid>/fd`. Корень `/proc` параметризован для тестов.
- `internal/registry`: запись сессии, публикация имени через `link()`, выбор
  свободного имени, живость по паре «pid плюс время старта», вытеснение мертвых
  записей, список.
- `rewake list` и `rewake whoami` работают по-настоящему.

Тесты: две одновременные публикации одного имени — выигрывает одна; мертвая
запись вытесняется, живая нет; переиспользованный pid с другим временем старта
считается мертвым; небезопасный каталог дает отказ с кодом 2.

Приемка: запись, созданная руками, видна в `list`; после убийства процесса
исчезает из `list`.

## Веха 3. Claude Code: запуск и доставка

- `internal/wrap`: запуск harness с унаследованным терминалом, сигналы
  (`SIGINT`/`SIGQUIT` игнорировать, `SIGTERM`/`SIGHUP` пересылать), снятие
  маркеров родительской сессии, публикация и снятие записи, код выхода harness.
- `internal/inbox`: формат сообщения и статуса, запись отправителем, цикл
  обслуживания с повтором `pending`, TTL, перенос в `done/`.
- `internal/harness/claude`: аргументы запуска (`--messaging-socket-path`),
  доставка строкой в сокет, заголовок `[rewake] from <имя> · <id>`.
- `rewake send` целиком: ожидание статуса, итоговая строка, коды 0/1/3.

Тесты: порядок доставки по `id`; `pending` повторяется и становится `failed` по
TTL; статус пишется атомарно; доставка в несуществующий сокет дает `pending`, а
после смерти сессии — `failed`.

**Живой критерий:** `rewake claude --model haiku` в одном терминале,
`rewake send <имя> "reply pong"` из другого — ответ на экране за секунды; `list`
показывает сессию; выход harness убирает запись и сокет, ожидающие сообщения
получают `failed`.

## Веха 4. Codex: запуск и доставка

- `internal/harness/codex`: поиск текущего треда по открытым lock-файлам с
  выбором по времени изменения, доставка через `codex queue`, разбор его ошибок
  (`no rollout found` — `pending`, `No active session` — `failed`), `CODEX_HOME`
  в записи сессии.
- Обертка Codex: вводная через `-c developer_instructions` со склейкой со
  значением пользователя, каталог состояния в `writable_roots` при
  `exclude_slash_tmp`.

Тесты: поиск треда на фикстуре дерева процессов и каталога `/proc`; выбор самого
позднего lock; классификация ошибок `codex queue` по тексту.

**Живой критерий:** `rewake codex`, затем `rewake send` до первого сообщения —
код 3 и `pending`; после первого хода сессии то же сообщение доставляется и
Codex начинает ход сам. Отдельно: `codex sandbox -P :workspace -- rewake send …`
доставляет в Claude Code — проверка пути через ящик, без обращения к модели.

## Веха 5. Вводная и разрешения

- Вводная обоим harness, флаг `--no-intro`.
- `--allowedTools "Bash(rewake:*)"` у Claude Code.
- Проверка, что флаг дополняет правила пользователя, а не заменяет их; если
  заменяет — флаг убрать и назвать в обзоре правило, которое стоит добавить один
  раз.

**Живой критерий:** запущенный через обертку агент на вопрос «кто ты в rewake»
отвечает своим именем, а `rewake send` выполняет без подтверждения. Для Codex —
тот же вопрос одним дешевым ходом.

## Веха 6. Готовность к ежедневной работе

- Уборка `done/` по возрасту, понятные отказы на краях (умершая сессия во время
  ожидания, занятое имя, недоступный каталог).
- `README.md`: что это, установка, три команды, граница доверия.
- Перевод ящика с опроса на inotify с запасным путем на опрос.
- Сборка под linux-amd64 и linux-arm64, публикация `@iiiokojiadbi/rewake` с
  платформенными пакетами; публиковать только по отдельному слову владельца.

Приемка: неделя работы без ручного вмешательства; ни одного случая, когда
сообщение потерялось молча.

## Риски

| риск | что делаем |
|---|---|
| приватный протокол сокета Claude Code меняется или выключается удаленно | доставка изолирована в адаптере; при отказе сокета — внятное `failed`, а не тишина |
| задержка Codex около 10 секунд смущает отправителя | пишем в итоговой строке прямо; в будущем — свой app-server |
| сообщение в свежий тред Codex висит `pending` | код 3 и текст, объясняющий, что доставится после первого хода |
| обертка умерла, harness жив | сессия считается мертвой; доставка отказывает с причиной, а не молчит |
| одинаковый текст подряд отбрасывается получателем | короткий id в заголовке каждого сообщения |
