# Stage 3 of 2.0: S11 built

S11 is the eleventh step of stage 3 ([stage3.md](../v2/stage3.md)): the host on the live
set ([stage3-steps-adapters.md](../v2/stage3-steps-adapters.md#s11-the-host-on-the-live-set-codex),
[design-api.md](../v2/design-api.md#two-levels-offered-and-live)). It was built on
October 11, 2026, on branch `s3-s11` from `a5dcebe`, in three commits, `e63688f`..`f447571`,
and this entry; one more commit after it makes the suite wait for the recipients it
sends to (below). The review round the same day found four defects and a wording, fixed in
five commits on top (below); the Codex side accepted it at `1cf4456` with two wording
corrections, made in the commit that records the acceptance.

## What the record shows now

Every fixture run's record carries its live set (`rewake list --json`, field `live`) and
its channel: a tool live, no tool and why, lost, denied by policy, the shell's evidence,
frozen at the exit. Before this step every session showed its mail channel as unknown.

## Decisions taken in the step

- A tool the readiness exchange did not make live keeps its offered record, unproven
  rather than absent, and the person is told on stderr that mail goes through the shell
  until it is live. A later connection that makes it live brings its hello, its calls and
  a denial into the record. The step first made such a tool no tool for the whole run;
  the review rejected that (R3, below).
- A letter to a run without a live Wake is Pending rather than Failed: it is written and
  readable, and a Wake that becomes live carries the next attempt.
- No `clear` command exists yet; the Control refusal covers `compact` and `interrupt`.
  [remote-control.md](../remote-control.md), the step's text and the capability table in
  [design-api.md](../v2/design-api.md#the-capabilities) say so, the command being designed
  in [conversation-reset.md](../conversation-reset.md) and not built.
- Claude Code's briefing keeps `Tool` false: no tool runs there since S9.
- The silent "not answering" mutant of fixture-steered retired with the observation it
  broke; `steers-unlive` replaces it.

## The review round

An independent review on October 11, 2026 found four defects, each with a probe; every
probe became a product regression and every fixed path has a mutant the regression kills.

- **R1, high: a run without a live Wake lost the letter.** The wrapper's reservation was
  assigned straight from the adapter and bypassed the Wake check, so the fixture's refused
  reservation failed the letter that `send` had reported accepted. `658a068`: a reservation
  and a conversation are asked only through a live Wake (`reserveIfLive`, `threadIfLive`);
  without one the inbox takes the plain path — a reserver answering no reservation is now
  part of its contract — and the letter is readable and Pending, owed a report in no
  conversation. `fixture-live` judges `send`'s own answer, the readable copy and the stored
  status; mutants `reserve-unguarded` and `thread-unguarded`.
- **R2, medium: `send` judged the boundary before reading stdin.** `9f8d22b`: the record is
  read again once the text is in hand, and a boundary withdrawn meanwhile refuses, exit 1,
  nothing sent; a record that cannot be read again fails the send.
- **R3, high: a tool live after an unproven exchange stayed no tool.** Its later hello,
  calls and policy denial never reached the record, so a denial left the shell's advice
  on (C7). `da6226c`: the record stays the offered tool's, the denial blocks the advice; a
  unit test walks the lifecycle, `fixture-live` holds the record unproven and never no
  tool; mutant `unproven-taken-for-none`.
- **R4, medium: a failed write of a withdrawal was swallowed.** The record kept the lost
  capability and other sessions kept acting on it. `79fad0e`: a set whose write fails is
  owed; the wrapper writes it once more at once and then with a growing wait up to a
  second until it lands or the run ends, never into a later run's record. Five unit
  mutants, each killed.
- **The `clear` wording.** The step listed `clear` among the refusals while the command is
  design only. `4f1640e` says so in the step and the capability table.

Accepted as the step chose: Pending without a Wake, Claude Code's briefing without the
tool, the ten readiness waits of the suite, the run's identity kept across liveness.

## Review round 2: accepted

The Codex side accepted S11 on October 11, 2026, at `1cf4456`, reviewing the six fix
commits against round 1: R1, R2 and R3 closed; R4's lost update closed by the retries and
the error on stderr; the `clear` wording closed; the round-1 choices stand.

R4 is closed for storage that writes or recovers. Persistent failure of session-record
writes is a stated limitation, not covered: there is no bound on the window in which
other sessions read the previous set while the writes keep failing, and remote admission
is not fail-closed then — another session can admit a task against a boundary already
lost until a write succeeds. The one-second bound is the retry interval, not a
publication deadline. A letter kept readable and pending does not prove its turn can be
reported. A probe holding those writes unavailable for 2.2 seconds while reads succeed
saw seven failed writes and the reader's record still carrying the boundary. Main scoped
persistent failure as degraded storage: the retries, the visible error and a truthful
account answer it in S11; a retry deadline, an authoritative read, a capability lease or
ending the session are not required.

Two wording corrections were made with this record: `docs/delivery.md` no longer bounds
that window to a second or two, and the comment in `internal/wrap/live.go` no longer
claims that the immediate retry leaves no moment in which a reader sees the old set.
