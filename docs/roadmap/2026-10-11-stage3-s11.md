# Stage 3 of 2.0: S11 built

S11 is the eleventh step of stage 3 ([stage3.md](../v2/stage3.md)): the host on the live
set ([stage3-steps-adapters.md](../v2/stage3-steps-adapters.md#s11-the-host-on-the-live-set-codex),
[design-api.md](../v2/design-api.md#two-levels-offered-and-live)). It was built on
October 11, 2026, on branch `s3-s11` from `a5dcebe`, in three commits, `e63688f`..`f447571`,
and this entry; one more commit after it makes the suite wait for the recipients it
sends to (below). It waits for review.

## The commits

- `e63688f` — the live set recorded: `registry.Session.Live`, written through
  `registry.Modify` under the name lock and only for the run's own epoch; the wrapper's
  `liveSet` takes each set a `LiveReporter` pushes — the fixture's readiness exchange, a
  withdrawal the moment its connection drops, the set again after a new exchange — and a
  run that reports none has live what its plan carries. The fixture's control, briefing
  and tool denial ride its connection: `control.Serve` answers a request while Control is
  live, the briefing is built once the exchange shows whether the tool is live
  (`brief.Context.Tool`), and a denial of a tool call reaches the endpoint's neutral input
  as the channel record's block. The channel keeper begins at the tool's attach and takes
  the shell's evidence each heartbeat.
- `ff46fa8` — the decisions: `send` to a run without a live Wake is accepted, exit 3,
  and the letter waits in the inbox (the wrapper's delivery stays Pending, nothing is
  woken); a task or a question to a run without a live TurnBoundary fails, exit 1,
  nothing sent — the offer only picks the wording, and S9's text stays for a harness that
  offers no boundary; `compact` and `interrupt` of a run without a live Control fail,
  exit 1, nothing asked; a reporting role's launch waits for its TurnBoundary up to
  `adapter.ReadinessBound` and is refused after, before the harness starts. The rule is
  held in [rules/host.md](../rules/host.md#the-live-set).
- `f447571` — the fixture column: the `fixture-live` case with ten observations and nine
  controls, one per decision and keeper transition; fixture-steered's "not answering"
  observation re-pointed at the refusal by liveness; the session state published once
  more on stop, so the channel record frozen at the run's exit stays.

## What the record shows now

Every fixture run's record carries its live set (`rewake list --json`, field `live`) and
its channel: a tool live, no tool and why, lost, denied by policy, the shell's evidence,
frozen at the exit. Before this step every session showed its mail channel as unknown.

## Decisions taken in the step

- A tool the readiness exchange did not make live is no tool for the whole run: the record
  begins again with why and the person is told on stderr. A later connection that makes it
  live serves calls; the record keeps no tool, as for a run that started without one.
- A letter to a run without a live Wake is Pending rather than Failed: it is written and
  readable, and a Wake that becomes live carries the next attempt.
- No `clear` command exists yet; the Control refusal covers `compact` and `interrupt`, and
  [remote-control.md](../remote-control.md) says so.
- Claude Code's briefing keeps `Tool` false: no tool runs there since S9.
- The silent "not answering" mutant of fixture-steered retired with the observation it
  broke; `steers-unlive` replaces it.

## The assertions the brief asked to search

Tests that send to a session started in the same test were searched twice. The first
search looked at the sends a session makes itself, which wait for their recipient's
listening file (`readinessSwitch`), written after the readiness exchange; `test/toolrig`
sends only notes, which exit 3 with or without a live Wake. It missed the sends main
makes through its request directory. The suite run on the last commit, eight cases at a
time, had two of them refused: a worker whose exchange finished after main's, and a task
to it with no live boundary yet. Ten cases in nine files sent that way to workers they had
just started — awaited-view, fixture-grant-dir, fixture-steered, fixture-turn-start,
addendum-owed, edit-after-notice, withdraw-after-notice, withdraw-mid-turn,
stopped-routing and turn-reasons — and each now waits for its recipients with `sessionsUp` before the
first letter (`test/workflow/wrapped_launch_test.go`), in the commit after this entry. The
assertions themselves did not change: what each scenario judges after the send is as it
was. The forgery case sends from the worker's own terminal, after its exchange, and needed
nothing. The trap is recorded in [testing.md](../testing.md#traps-this-suite-has-already-paid-for).
