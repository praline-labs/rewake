# Stage 3 of 2.0: S9 built and accepted

S9 is the ninth step of stage 3 ([stage3.md](../archive/v2/stage3.md)): Claude Code's hook
machinery leaves the product, and Claude Code offers Launch and Wake only until stage 4
gives it a turn boundary
([stage3-steps-adapters.md](../archive/v2/stage3-steps-adapters.md#s9-claude-codes-hook-machinery-leaves)).
It was built on October 11, 2026, on branch `s3-s9` from `98acc3b`, in four commits,
`fc0d1e0`..`afcc56a`, and a correction, `12e8799`. The review round on the Codex side the
same day passed three of them and asked for changes in two; the fixes landed as four new
commits, `3feffb2`..`e07660e`, with this record of them.

## The refusal

As the owner decided on October 5, 2026: a launch of a role that owes reports — general,
worker, write — on a harness whose contract reports no turns exits 1, naming the missing
turn boundary and that the role is available on that harness from stage 4; `--main`
launches. A task or a question to a session on such a harness exits 1 and sends nothing;
a note still goes. The harness is asked before the role: every Claude Code session is a
main, and a question to it is refused for the missing turn boundary, exit 1, not by main's
own exit-2 refusal, whose advice to send a plain task would only be refused next (R1
below; the live check recorded the earlier order). `internal/cli/turn_reporting.go`
decides both from the adapter's contract; tested by
`TestAReportingRoleDoesNotLaunchOnAHarnessThatReportsNoTurns` and
`TestATaskToASessionThatReportsNoTurnsFails`, whose recipient is a main;
`TestAQuestionToASilentSessionIsRefused` keeps main's refusal on a harness that reports.

## The live check, October 11, 2026

The question: does the 1.x messaging line still wake a Claude Code main with the hooks
gone? Run on a build of the S9 working tree on `fc0d1e0` — the product code of
`6c8c88c` but for one doc comment changed after — with Claude Code 2.1.296, the version installed that day (the brief named
2.1.294).

- **Where.** A case folder `.scratch/s9-live/wake/`, its own git root, the caller's
  `--settings` excluding this repository's `CLAUDE.md` and `AGENTS.md` and allowing
  `Bash(rewake:*)`, a tmux server of its own (`tmux -L s9live`), launches through
  `env -u REWAKE_SESSION -u REWAKE_EPOCH -u REWAKE_DIR -u REWAKE_ROOM`. The state
  directory is `/tmp/s9l/wake`, linked from the folder: under the folder the socket path
  passed 103 bytes and the launch exited 1 saying so. The folder's trust dialog was
  answered once.
- **The launch.** `rewake --main claude --model haiku --settings <case>/settings.json`.
  The harness ran with `--messaging-socket-path` and `--append-system-prompt`, and no
  `--plugin-dir`, hook settings or status-line tap.
- **A send from outside a session is allowed**: a plain shell with `REWAKE_DIR` set ran
  `rewake send main-claude "..." --notify` and got `delivered to main-claude via socket`.
- **A note while idle.** The pane showed `● Rewake: shell notify, 1 new message` with the
  first line, and a turn started. A one-line note was answered from the notice alone and
  stayed unread; a two-line note whose request was on the second line made the session
  run `rewake inbox`, answer, and both letters were `read`.
- **A note during a turn.** While main ran `sleep 40` for an earlier note, a second note
  was sent: the notice showed in the running turn, 22 seconds in; once the command
  returned, the session ran `rewake inbox` in the same turn and answered both requests.
  The four letters ended `read`.
- **The refusals.** `rewake --write claude`, `rewake --general claude` and plain
  `rewake claude` each exited 1 with the stage-4 text. A task to `main-claude` exited 1:
  `main-claude runs Claude Code, which has no turn boundary in this rewake, ... nothing
  was sent`. A `--question` to it exited 2 with the earlier usage refusal, `Session
  main-claude does not report its turns, so it cannot answer --question`: main's role
  answers it before the harness is asked, and every Claude Code session is a main now.
- **Outcome.** Wake works without the hooks, idle and mid-turn. The evidence is in
  `.scratch/s9-live/evidence/` — the pane captures, the sends, the refusals, the
  statuses and the version — and not committed.
