# Stage 3 of 2.0: S15 built

S15 is the fifteenth step of stage 3 ([stage3.md](../v2/stage3.md)): the delivery server
to `host/delivery` ([stage3-moves.md](../v2/stage3-moves.md), the places from
[stage3-packages.md](../v2/stage3-packages.md)). It was built on October 11, 2026, on
branch `s3-s15` from `27cc2b5`: a record of the decided cut, preparatory commits in place,
the move, and this entry. The step goes to review and to acceptance on the Codex side.

## The cut

The inventory found the server's files and `core/mail`'s record code tangled both ways:
seven `(*Server)` methods sat in mail's files, and the bodies of the finished sweep, the
settlement and the awaiting sweep reached mail's private stop and copy handling. The cut
decided before the build: those three bodies stay in `core/mail` as locked entry points
(`SweepFinishedLocked`, `SettleLocked`, `SweepAwaitingLocked`), each called with the
mailbox lock already held; the server keeps the lock, the live-run check and the order
around them; a layout test holds the callers of the three to the server methods that
take the lock; and tests that need to fail a waiting copy's removal or watch the stop
listing do it through two operations of `core/mail` built only under `rewakefault`.
`9593ae9` records the cut in the plan before the code that relies on it.

## The preparatory commits

Each changes no behaviour, and each was shown not to by a per-function comparison of the
source:

- **The methods** (`3d05f4b`): the seven methods moved to the server's files, the three
  locked bodies extracted under their entry points, the lock and the live-run check left
  in the methods around them.
- **The sides** (`5e9e876`): identifiers only mail uses moved to mail's files and those
  only the server uses to its own.
- **The names** (`0e08407`): the mail names the server calls exported, each with a comment
  saying why the server needs it.
- **The callers** (`67b9210`): `internal/layout_callers_test.go`, which fails when
  anything but the server's locking methods calls a locked entry point.
- **The fixtures** (`1307a20`): `core/mail/mailtest`, the record paths and bytes tests
  outside mail need, each checked in mail's tests against mail's own reader or writer.
- **The tests** (`b941b20`, `b5c3939`): the tests bound for the server moved onto
  `mailtest`, `state.Fault` and mail's exported operations; mail's own sweep tests sweep
  through the locked entry point under the real lock; the gate tests — the live-run check
  and the lock — on a lab of exported operations. Two package variables that only tests
  swapped were inlined to the calls they held.
- **The tagged operations** (`c479ff6`): `FailWaitingRemoval` and `AfterStopListing` in
  `core/mail/faultops.go`; five tests use them, and the removal case of the report
  recovery became its own tagged test.
- **The split** (`2133d97`, `97ab6bb`): the server's tests cut out of mail's mixed test
  files unchanged and recorded in the file group; the reservation order test moved from
  the fixture's adapter to `test/toolrig`, the test playing the program through a relay.

## The move

`ba0b7f4`: `git mv` of eleven production files and forty-five test files to
`internal/host/delivery`, `package delivery`, every mail name qualified by a `go/types`
pass over the four build variants, twenty-two shared test helpers copied into
`lab_test.go`; the consumers in `wrap`, `cli` and `test/toolrig`; the file group entry
removed; the callers' table, the name exceptions, the mutations' files and texts, the
suite's `-X` values for the coalescing window; the citations in [rules/](../rules/README.md),
the paths of the living documents and the line of `host/delivery` in [code.md](../code.md).
Every moved file is the original but for the package clause, the import block and the
`mail.` qualifier. The dated records and the plans of [v2/](../v2/README.md) keep the
paths they were written against.

`core` imports no `host` package in any variant, with tests or without; the five checks
and the workflow suite pass on the move.
