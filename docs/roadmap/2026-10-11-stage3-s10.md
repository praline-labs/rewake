## The API

`internal/adapter` holds the capabilities ([code.md](../code.md#the-adapter-api)):

- **Offered**, before any launch: `Harness.Offers()` returns an `Offer` — Wake, the tool
  transport, the turn boundary (reports, can hold an end), Telemetry, the Control verbs
  (compact, interrupt, a compaction's focus, the trace an interrupt leaves), Permissions
  (a directory, Git metadata, a main's grant reaching its wrapper) and PersonUI. The CLI
  asks it through `Catalog.Offers(id)`, zero for an unknown id: `send --grant-dir`,
  `--grant-git`, a main's grant, `rewake compact` and `rewake interrupt` (each verb on its
  own now) and the reporting-role refusal read it.
- **Served by one run**: the plan carries interfaces the wrapper calls — `Service`
  (started before the harness, a failed start ends the launch, closed with it; a
  `ProcessService` when it owns a process), `Wake` (with `Reserver` and `Receiver`
  where the run answers before the letter), `TurnBoundary` (handed a `TurnHandler`
  before the service starts), `Telemetry` and `Thread`. A tool transport is the
  service's `ToolTransport[D]`, generic over the descriptor because the descriptor lives
  in the tool layer, which the API does not import. `ThreadTracker` takes a
  `RunProcess`, pid and start, not the session record; `Resumer` and `WorktreeHarness`
  stayed as they were. **Live**, per run: `LiveReporter`, which the fixture's readiness
  exchange answers with the capabilities it made live, named on the wire by the API's own
  names; S11 records it.
- **The turn end**: `TurnEnd` names its event and its reason — answered, aborted,
  refused, failed — with the answer in the harness's words and the scope. The core
  refuses an end with no event or an unknown reason, on the published path and the
  confirmed one, and derives the report from the reason. Refused reports an error, as
  failed does (a decision of this step; [turn-outcomes.md](../turn-outcomes.md#failed-turns)).
- **What left**: `Backend`, `ProcessBackend`, `ReservingBackend`, `ObservedBackend`,
  `Lane`, `Observer`, `TurnReporter`, `CompletionHandler`, `Completion`, `Steerable`,
  `GitGrantHarness`, `DirGrantHarness`, `TurnReportingHarness`, `GrantIssuer`,
  `LaunchRefuser` (no adapter offered it since S8) and `Harness.Deliver`. No interface
  carries `registry.Session` whole; `internal/adapter` imports only core and infra.

## Review round 1

review-codex reviewed `d685817..19a7bf0` on October 11, 2026 and accepted everything but
one finding: the catalogue and imports, `Offer` and the plan, the retired endpoint paths,
the turn ends, the four retargeted controls, the helpers and the protected directories,
and `Refused` reporting as an error.

- **R1, a boundary without a tool lost its starts** (`e433453`). A start reached the host
  only through `TurnHandler.Tool`, which a run without a mail tool — or with one that could
  not start — does not have, so `inbox.RecordTurnStart` was never called and a pending mark
  of a turn whose end was lost could not be found over. `TurnHandler.Started` now takes
  every start, tool or none: the wrapper records a timed start once and, where the run has
  an endpoint, opens the turn in its table; `ToolInput` keeps the end, the calls and their
  results and loses `TurnStarted`, and the endpoint records nothing. Held by
  `TestABoundaryWithoutAToolRecordsItsStart` (the reviewer's probe as a product test),
  `TestABoundaryWithAToolRecordsItsStartOnceAndOpensItsTurn` and
  `TestALostEndWithALaterStartOnRecordMarksNothing`, named in
  [rules/tools.md](../rules/tools.md); the endpoint's start test retired with its record.
  [design-api.md](../v2/design-api.md#turnboundary) says it.
- **The declining clause** (`19b8318`): "Claude Code and fixture takes none" — the clause
  now takes a phrase for one harness and one for several
  (`TestADecliningClauseAgreesWithHowManyDecline`).
- **The launch secret** (the review's item 4) is not a blocker and is left as it is: if it
  is simplified later, the fallback admitting a descendant the endpoint did not run goes
