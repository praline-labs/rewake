# Stage 3 of 2.0: S6 built and accepted

S6 is the sixth step of stage 3 ([stage3.md](../v2/stage3.md)): the fixture column becomes
the workflow suite's regression gate
([stage3-steps.md](../v2/stage3-steps.md#s6-the-fixture-column-becomes-the-gate),
[stage3-fixture.md](../v2/stage3-fixture.md#the-gate-across-the-steps)). It was built in
one commit, `be7832c`, and accepted on October 8, 2026 after one review round, with one
documentation edit that lands in the commit adding this entry.

## The commit

- **The gate is a column's field**, set on the fixture column only; `isGate` and
  `gateColumn()` read it from the one list of columns, so no decision is keyed to a
  harness name any more.
- **One exception**, in a table of its own: conversation selection on the fixture,
  with its reason and the step that retires it, S8. Ordinary tests require exactly one
  gate and that it is the fixture's, the gate to declare every capability a scenario asks
  about but the excused ones, and every exception to still match — no duplicate, no
  unknown capability, no column off the gate, no capability the gate declares, a reason
  and a step on each. Unsupported stays a failure on the gate.
- **Selection's observations become the Codex column's own**: task-report's and
  batch-arrival's are recorded only on a column that offers selection, where before the
  other columns recorded them as unsupported. Readiness there is proven by the
  recipient's own file. mid-turn's readiness observation shares the wording, is not one of
  the two, and stays on every column.
- **`node` is keyed to the Claude Code column by name**, not to the absence of selection.
- **Every control follows the gate.** The mid-turn controls and the controls of neutral
  scenarios that were wired to the Claude Code column run on the gate; task-report's
  shared controls run on all three columns, its two hook controls stay on Claude Code.
  The two mutants that broke the Codex gateway would break a file the gate never runs, so
  they were replaced by their equivalents in the fixture adapter: delivery waits for an
  idle session, and a recall loses the task it names.
- The summarizer's prose and the testing documents say the gate is the fixture column.

  selection ones; the crosswise check's 35 pass with identical observations. The 45
  others are the Codex column's own scenarios — its adapter families, three readiness
  controls, the second terminal event and the schema check — kept on their column; none
  had a fixture case before, and S8 removes them with the column. The growth is the
  task-report controls on the third column. The review repeated the comparison on the
  raw records.

  recorded first and after: every exit code 0; the test runs passed 5198 untagged and 5261
  with each tagged variant, the two more than S5 being the two new gate tests.

  name-keyed `isGate`, the wrong `gateColumn`, a gate without mid-turn, and the
  exception table dropped, stale, unknown, off the gate, doubled or without a step.
