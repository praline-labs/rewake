# Stage 4 of 2.0: the probe's first runs

The first runs of stage 4's probe ([design-claude.md](../v2/design-claude.md#the-stage-4-probe))
and the owner's decisions they led to, all of October 13, 2026, on Claude Code 2.1.296 with
the `mods` skill of the same version. Main ran every probe live, from a kit kept in the
ignored `.scratch/`; the write session built the kit and recorded the results on branch
`s4-probe-docs` from `v2` at `dd29171`. Documents only: no code changed. The records are
[research-claude-mod.md](../research-claude-mod.md).

## What ran and what it answered

- **P11, the first half** (runs `nugmw7`, `b19RdW`, `jOyBP5`). A process the mod starts at
  its first `session.start`, before any prompt, can detach, outlive a module reload and end
  with the harness process; before it detaches its parent is the harness process itself. A
  child of `$.process.spawn` that does not detach is terminated at every reload. The second
  half — the three authority obligations of the mod's join — did not run.
- **P12b, the keeper** (runs `woP6c8`, `tZXlTa`, `SNr8JH`, `jFP9oG`, `FKFkzX`). The mod
  spawns a subagent of main with worktree isolation itself, with no turn of main's model,
  and holds it by a blocking tool whose call it keeps alive by polling under the 30 s each
  `$.http.fetch` is allowed. Claude Code branches the checkout from `origin/main`, not from
  the checked-out branch, locks it under its own reason, and removes an unchanged checkout
  when the keeper ends. When main exits while the keeper still runs, the checkout stays,
  locked under a dead pid, and a process inside it keeps running; Git takes one lock per
  worktree, so rewake cannot add its own. A named spawn gives an ordinary subagent, not a
  teammate. A background session as keeper refused in an untrusted directory.
- **P15a, the tab** (runs `K7pYUU`, `EMheCZ`, `lIxo7H`, `UqTei1`). The keeper's tasks-list
  entry opens its view, and in it the mod draws into the keeper's tool row: a grid repainted
  once a second, up to 196 by 44 cells in a 200 by 50 terminal without fullscreen, with
  about 16 rows left to Claude Code's chrome. Letters, Alt as `meta`, F1, the arrows and Tab
  reach the mod's input; Escape, Ctrl+C, Ctrl+X and a paste do not.

## The decisions

- **Workers close with main** (the owner): no design keeps a worker alive past its main;
  each worker's session id is recorded so that main can restore it. The keeper is therefore
  a subagent of main, the background-session keeper is dropped, and so is P16, headless and
  background workers ([answer 7](../v2/design.md#the-owners-answers)).
- **Kept checkouts are reminded**: a checkout a closed space leaves with changes stays in
  the space's record, and rewake reminds main of it until it is merged or removed
  ([the target](../v2/stage4-audit.md#the-target-a-space)).
- **A room is one main by default** (the owner): main, its spaces and its workers; the room's
  scheme stays in the core for communication between mains later
  ([answer 8](../v2/design.md#the-owners-answers),
  [design-state.md](../v2/design-state.md#the-state-root-of-20)).
- **A prefix key** carries the keys the mod's input does not receive: an Alt chord, then a
  key for Ctrl+C, Escape or Ctrl+X, the chord twice for itself; paste stays open
  ([two levels of UI](../v2/stage4-audit.md#two-levels-of-ui)).
- **Go and TypeScript** (the owner): Go for the core and every adapter's host side;
  TypeScript only for an in-harness part that must be, the Claude Code mod and pi's
  extension, generated or embedded by the binary, with the protocol described once as a JSON
  schema and the TypeScript types generated from it ([answer 9](../v2/design.md#the-owners-answers)).
- The teammate question is closed by the first decision: a keeper that outlives main has no
  purpose.

## What stays open

- P11's second half: the caller-to-final-writer proof, a late opt-in, the harness's death
  during an admitted decision; and `session.end` without an exit, a respawn of the hooks
  worker, the harness killed outright.
- P15b: a real pseudo-terminal with its screen, the prefix key end to end, which Ctrl keys
  reach the mod's input, paste, the largest grid in fullscreen, the pane as a second place,
  the cost of a redraw.
- The keeper's checkout: the base of the work's branch, since Claude Code branches from
  `origin/main`; who sweeps a checkout a main's exit left locked; how the mod releases the
  keepers at `session.end` early enough for Claude Code's own cleanup; Git writes inside the
  checkout.
- The second `space_hold` call in run `woP6c8`, under an agent id `$.agent.list()` never
  showed: unexplained.
- The `mods` skill states neither the 30 s limit of `$.http.fetch` nor that a change to the
  mod's file under `--plugin-dir` was not reloaded in this run.
