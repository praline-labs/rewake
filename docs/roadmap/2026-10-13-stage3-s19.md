closed, the layout test's tables empty, the documents and `AGENTS.md` brought to what the
stage built, and the stage handed to its acceptance on the Codex side. By the owner's

## Known limits

Recorded where they apply, each owned by a later stage or kept by decision:

- **S11**: persistent failure of session-record writes is degraded storage — no bound on
  the window in which other sessions read the previous live set while the writes keep
  failing ([S11's entry](2026-10-11-stage3-s11.md)).
- **S15 N1**: three tests of the delivery server do not yet assert the waiting copy while
  the fault is installed; a test improvement owned by stage 7, with the documents' and
  tests' clean-up ([S15's entry](2026-10-11-stage3-s15.md#open)).
- **S17, part 1**: the caller check reads no types, so a same-named local in a file with a
  dot import counts as a reference; a worker that never returns holds the lease until the
  process exits, on purpose.
- **S17, part 2**: `Authorize` and `ClaimSocket` are scoped by the lease they need, not
  restricted to their callers; the static check reads no types; the claim tells a state by
  what is on disk at each act, so a link swapped between check and act is not seen; the
  adapters do not use the run directory yet, which the adapters of stages 4 and 5 take up.
- **S17, part 3**: a crash between a tree's deletion and its counts leaves that small file
  under `v2/`; the clearing assumes the pid namespace of the 1.x sessions; a flush after
  another clearer's failed one is taken on the kernel's word
  ([S17's entry](2026-10-11-stage3-s17.md#open)).
- **S18 N1**: a resolved occurrence whose record no longer reads stops the barrier, while
  the decide list does not show it
  ([stage3-decision.md](../v2/stage3-decision.md#the-command)). A wrapper started from an
  older binary ignores the deadline a newer command sends; the inbox-level link limitation
  stays documented; crosswise does not run the decide controls against other families
  ([S18's entry](2026-10-12-stage3-s18.md)).
- **Minimum versions**, owned by stage 4: the note of a version newer than the last live
  check is not built, and the oldest supported versions in `docs/legacy.md` do not yet hold
  the adapters' minimums ([adapter-api.md](../rules/adapter-api.md#minimum-versions)).
- **Claude Code's side**, owned by stage 4: a reporting role, a task and a question are
  refused on it, and the suite has no Claude Code column or inbound lane end to end until
  the adapter offers a turn boundary ([S9's entry](2026-10-11-stage3-s9.md)); grants on
  Claude Code wait for stage 6.
- **The launch secret** in the endpoint's ticket stays as it is
  ([S10's entry](2026-10-11-stage3-s10.md)): whether a child the endpoint ran still needs
  it is decided by the stage that next builds a tool transport on a real harness.

## Where stage 4 starts

Stage 4 builds Claude Code's adapter as one mod, and it starts with an audit, before the
probe and before any adapter code, by the owner's decision of October 12, 2026
([design-claude.md](../v2/design-claude.md#before-the-probe-what-claude-code-already-does)):
each feature 1.x wrote before mods existed — the settings hooks, the telemetry collector,
the wake line, the worktree launch — is weighed against the installed Claude Code and the
`mods` skill, and kept as rewake's, handed to a native feature or built on a mod event.
Only what survives the audit goes into the adapter or the probe.
