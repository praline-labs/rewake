# Stage 3 of 2.0: S3 built and accepted

S3 is the third step of stage 3 ([stage3.md](../v2/stage3.md)): one landing per copy. It
was started on October 5, 2026 and accepted on October 6, 2026, Codex side included, in
two commits. The first holds every once-publication inside its recipient's lock, by the
contract of [stage3-publication.md](../v2/stage3-publication.md); the second makes a stop
one write-once record per occurrence of a cause, resolved only by evidence about its
effect ([stage3-steps.md](../v2/stage3-steps.md#s3-a-stop-is-resolved-per-cause-by-evidence-codex)).
Both commits went through the Codex-side review together while the first was open, then
the second alone: three rounds for the first, six for the second. Each round's
counterexamples were probes added through a test overlay and run by main; each fix turned
them into product tests and ran mutants over the touched code.

## Commit 1: the publication inside the lock, in three rounds

The publication's liveness check, its evidence reads and its write share one critical
section of the recipient's lock (P1), the proof is retired only there, by the live run
(P2), the reads use the read-only lookup (P3), and the sender's own mailbox lock is not
taken twice (P4). Committed as `749aceb`.

1. **Refused.** Settling could remove a letter's last copy: an archive that failed was
   followed by dropping the readable copy anyway. A crash between the letter and its
   published mark leaves only intent, so a lost letter made the publication read absent
   and let an ordinary retry write the same id again. Settling now never removes a copy
   unless another stands. Two side findings: the endpoint test
   `TestServerConnectionsAreNumberedAndTheirClosesNamed` assumed that dial order is
   generation order, a scheduling fault in the test and not a race in the code, fixed
   by waiting for the first connection's event; and a mutant reported equivalent
   (`letter-ignored`) changed an observable result, so a regression was added for it.
2. **Refused.** The last-copy check took a directory or a dangling symbolic link at a
   stage path for a copy. Only a regular file counts now.
3. **Accepted**, Codex side included.

## Commit 2: the stop by occurrence, in six rounds

A stop is a record per occurrence of a cause. An occurrence is resolved only by evidence
about its effect, never by its path becoming absent or readable. A moot disposition
never closes it, and a cause that recurs after its resolution is a new occurrence.
Unknown records stay unknown in the awaited, owed and list views. A copy that an open
occurrence names, or one inside a directory it names, is kept by every remover, not only
by the sweeps.

1. **Refused, three findings beside the inherited last-copy one.** An existence check
   that failed was recorded as absence, so an unreadable path could later read as
   evidence. A resolution that did not read was accepted. Paths that a stop names still
   disappeared outside the sweeps. Presence is now present, absent or unknown. A
   resolution is read before it lifts a stop. Settling and releasing keep named paths.
2. **Refused.** A non-empty evidence list could still name no evidence. Settling still
   had an unlocked fallback that removed a path a concurrent stop had just named, since
   a lock whose file cannot be opened does not prove that nobody holds it. Settling now
   runs only under the real lock. When the lock cannot be taken, only the status is
   written alone. The same round decided ENOTDIR: an ancestor that is a file proves this
   path absent at that moment, and nothing about an earlier landing. EACCES and I/O
   errors stay unknown.
3. **Refused.** Two kinds of settling were never retried once the lock worked again: a
   foreign letter refused at the start, and a late refusal whose readable copy was the
   only one left. The passes were given a set of deferred settlements.
4. **Refused.** That set was memory: a restart lost it. A lock callback that ran was
   also taken for a finished settlement, even when a stop or a failed archive left the
   letter. The set was removed. What is owed is now read from the status and the
   copies, at a run's start and on every pass, under the retry throttle. `settle` says
   whether the letter stands where its outcome puts it.
5. **Refused.** The foreign recovery path settled by a status read before the lock. A
   withdrawal made while it waited for the lock lost its tombstone. The review also
   corrected the writer's mutant report: of the two survivors, only the one that removes
   the outer claim pre-check keeps the protection, since `settle` checks the claim under
   the lock. The other, which let a withdrawn status owe the archive, is killed by a
   concurrent withdrawal.
6. **Accepted**, Codex side included. The status that settles a letter is read again
   under the lock that moves it. A withdrawal, a read, an available report or a claim
   found there decides. A status that does not read defers to the retry interval. The
   race tests use the lock-wait event, not sleeps.

The workflow suite gave the same outcome per case before and after each commit: 163
cases, 160 passing and the same three unsupported.

## What stays open

- S5–S19 in the order of the build table, S18 on part B's accepted rules; S4 is in
  [its own entry](2026-10-06-stage3-s4.md).
- An unknown path that an occurrence names waits for the operator decision of S18. That
  includes a stop whose first look failed and whose path is now absent: initial absence
  was never established.
- The status-only fallback writes a status without the lock on purpose. Recovery after
  the process is lost relies on the outcome being durable: an outcome whose status write
  failed is retried only by the run that holds it.
- `list` still calls the registry listing that cleans dead records before its read-only
  pass over unreadable ones, so the command as a whole is not free of cleanup.
