# A directory granted with a task, stage 1 — September 27, 2026

The owner decided on September 27, 2026 that main may give a worker write access to a
directory outside its workspace for one task, and settled the same day how it is
checked, how long it lives and how it is taken back ([grants.md](../grants.md)). Stage 1
is the shared part and Codex; Claude Code follows in stage 2
([work-queue.md](../work-queue.md#now-what-the-directory-grants-and-the-worktrees-left-open)).

## What was built

- **The flags.** `rewake send --grant-dir <dir>` and `--grant-dir-broad <dir>`, both
  repeatable, at most 8 together, from a verified main on a task or a question. A
  command-table option can now be `Repeatable`: its values collect in `Call.Lists`, and
  the guide says so. Any other flag given twice is refused with exit 2 where the last
  value used to win silently; no example or test repeated one.
- **The check at send** (`internal/grant`). A directory is resolved from the sender's
  directory, cleaned and resolved through links, and must be a directory (exit 1
  otherwise). The hard tier refuses what is, lies inside or contains rewake's own state,
  configuration and binary, a harness's configuration (the new `ProtectedDirs()` of each
  harness), login keys, `PATH`, git and systemd configuration and the system
  directories; the broad tier — `/home`, `/mnt`, `/media`, the mounts under them, each
  directory directly in `$HOME`, each `~/.config/<app>` with a `credentials` file — needs
  `--grant-dir-broad` with the same path. Both refuse with exit 2 and say what matched
  and what to do instead. Paths are compared by elements, case-folded under
  `/mnt/<letter>`. A directory in the worker's workspace is named already writable and
  not carried; nested ones collapse to the outermost. A Claude Code recipient is refused
  with exit 1 until stage 2.
- **The check at delivery.** The recipient's wrapper runs every check again with its
  own environment and requires the path to resolve to itself; a task whose grant fails
  is not delivered, and its sender gets a note.
- **The idle wait.** A message carrying a grant, `--grant-git` included, goes on a
  notice of its own. The Codex adapter reads the thread before the task becomes
  readable and keeps it pending while the thread is active. This changes `--grant-git`,
  which used to steer into a running turn and share a group
  ([git-grants.md](../git-grants.md)).
- **Codex's roots.** The granted directories are appended to the snapshot's
  `runtimeWorkspaceRoots`, with each granted checkout's Git metadata when `--grant-git`
  rides along; the sandbox and the other roots stay.
- **Taking it back.** A journal per session run, under the room's `grants/`, records
  what rewake added — path, task, time, outcome — and `rewake list --json` shows it as
  `grants`. At any later delivery the adapter takes out what tasks since settled were
  given, keeping a directory another live task holds.
- **Visibility.** `grantDirs`, `grantApplied` and `alreadyWritable` in `send --json`;
  `grantDirs` and `grantBroad` in the message; the outcome in the status `detail`; a
  `grant: write <dir>` line above the task in `rewake inbox` and `--owed`.
- **The launch.** `rewake codex --add-dir` and a `writable_roots` override are refused
  with exit 2 and a pointer to `--grant-dir`: the terminal refuses both beside
  `--remote` from Codex 0.156 on ([traps.md](../traps.md#rewake-codex---add-dir-exits-1-on-codex-0156-and-later)).
- **The briefings.** Main is told when to grant, how to confirm a broad directory, that
  a grant is for writing, and that the hard tier is the owner's to give; write and
  general are told what the `grant:` line means and that it ends with the report.

## Tests

Unit tests in `internal/grant` over a built home — relative and `.`-laden paths, a link
to a directory and a link to a protected one, a file, each hard rule's three relations,
the broad tier with and without confirmation, drive letters in either case, elements
rather than prefixes, nested grants, a link changed since sending, mountinfo escapes, and
the journal's cap; in `internal/cli`, the send path end to end with every refusal and its
exit code, the reader's `grant:` lines, repeatable flags and the refusal of a repeat, and
the launch refusal; in `internal/inbox`, a grant alone on its notice while mail after it
goes on, a failed recheck and an expired grant failing without a reservation and telling
the sender, and when a task counts as settled; in `internal/harness/codex`, a grant
added, journaled and taken back, one dropped by a person's turn, a directory covered
already, one held by two tasks, a checkout's metadata, the idle wait and a snapshot that
cannot be read. Eleven hand mutations of the rules, the wait, the revocation, the
grouping, the recheck and the send path were each killed by these tests.

The workflow case `codex-grant-dir` runs on the Codex column: the fixture now keeps the
thread's workspace roots, reports the status of a turn in progress on `thread/read` and
records which roots each delivery carried. A task granting a directory, sent while the
worker's turn is held open, is accepted pending, goes on a turn of its own after that
turn closes, carries the directory beside `/work`, and after the report the next task
carries the roots without it while `rewake list --json` shows it revoked. Its three
mutants — no idle wait, a directory journaled but not added, a directory kept after the
report — each break what they name and nothing else
([testing-cases.md](../testing-cases.md#a-directory-granted-with-a-task)). The shape case
checks the fixture's `thread/read` reply against `ThreadReadResponse`.

## What stays open

- Stage 2: Claude Code through the `PermissionRequest` hook.
- A worker could forge a grant; closed the same day ([entry](2026-09-27-grant-unforgeable.md)).
- A grant whose task is settled lives until the next delivery to that session; nothing
  runs between deliveries to take it back sooner.
- The terminal can start a turn between the adapter's read and its `turn/start`; the
  grant then holds from the turn after.
