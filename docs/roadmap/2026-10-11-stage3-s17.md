# Stage 3 of 2.0: S17 parts 1 and 2 accepted

S17 is the seventeenth step of stage 3 ([stage3.md](../v2/stage3.md)): the state root `v2/`,
what is a writer, one build per room, the run directory and the measurement of the hash
([stage3-state.md](../v2/stage3-state.md)), with the clearing of 1.x
([stage3-upgrade.md](../v2/stage3-upgrade.md)). The Codex side's readiness review of
October 11, 2026 found the plan's five commits unable to meet their own assertions; main
adopted its corrections and decisions D1–D12 on October 12, and the plan was rewritten to
seven commits in three parts, each reviewed and accepted on the Codex side before the next
starts. S17 is built on branch `s3-s17` from `ab8d752` and lands on `v2` as one step after
part 3. This entry records part 1 — commits 1–3 — built and accepted on October 11, 2026,
and part 2 — commits 4–6 — built, corrected over four review looks and accepted on
October 12, 2026; and part 3 — commit 7, the clearing of 1.x — built on October 12, 2026,
not accepted at its first review the same day, corrected, and awaiting the review of its
fixes.

## Part 1: the contracts, the lease and the roots

- **The contracts** (`7f008e9`): the state plan rewritten to the seven commits, the form
  table, the exact view guarantee (D3), the widened write seam, the lock order (D4), who owns
  the lease (D5), the bootstrap (D6), holders named by pid and a safe label (D10) and the
  qualified guarantee of the run directory (D11); the upgrade plan and `design-state.md`
  corrected to D1, D4 and D7–D9.
- **The forms** (`235616f`): every parsed form of the command table carries its class,
  `view` or `change`, and a table test fails on one without; every authorized tool call is a
  change (D2). One scope runs from the class through the handler, the shell observation and
  a tool call's bounded output. Views stop pruning: `ownRun` and `list` read without pruning,
  the playbook resolves the current room, a view is never observed.
- **The build id, the lease and the bootstrap** (`a239c19`): `infra/build` hashes
  `/proc/self/exe` with SHA-256; `build.lock` with `flock(2)` and `build` beside it, taken
  shared by writers and switched exclusive without waiting by a launch, the record read again
  after every reacquisition and after the downgrade; holders found by device and inode; the
  bootstrap primitives of `infra/state`, which only the acquisition calls; both dispatch
  routes and the direct entry of the host acquire; `--version --json` carries the id; the
  endpoint's peer check compares the content id. Process races run real separate binaries in
  `test/leaserig`.
- **The roots** (`0ed6a30`): `Base`, `Root`, `RoomDir` under `v2/`, the checked inverses,
  resolvers that create nothing, the child's base round trip and the grant split between the
  base and the root; every path oracle of the tests corrected.
- **View mode** (`64909ad`, `adbde1c`): a view form puts the process in view mode, every
  write primitive refuses with `ErrViewWrite`, the attempt is kept as evidence, so a view
  that swallows the error still fails; a view of another build warns once on stderr.
- **D4a** (`1c3a567`): the workflow suite found two launches of one build into a fresh room
  refusing each other. A refused exclusive request is not yet a refusal: the launch reads the
  record again under the shared lock and is granted on its own id, or retries for two
  seconds before it refuses naming the holders.

Mutants: 21 for commit 2, 17 for commit 3 and two for D4a, each killed by the test it was
written for, through `-overlay`; the forms' mutants likewise.

## Review: six findings, then one follow-up

The review on the Codex side, at `1c3a567`, did not accept part 1. Main ran its six probes,
each confirming its defect; the fixes, each with a regression red before and green after:

- **R1** (`bd185b1`): the host released the lease while a stop that waited only 500 ms left
  an admitted publisher able to write. The run now keeps its own hold on the lease
  (`build.Lease.Keep`) until every worker that may still write — the availability publisher,
  the session-state worker, every live-set write and retry — has returned; a stopped live
  set starts no write.
- **R2** (`80fb319`): a refused acquisition still wrote a shell observation. A refusal now
  only prints.
- **R3** (`b8f75ec`): a retry of the bootstrap took an existing level for durable after its
  parent's sync had failed. Every level, made or found, is synced into its parent.
- **R4** (`b751283`): a refused writer created `build.lock` in a room a launch had left
  incomplete. A writer opens the lock without creating it, the first time and on every
  reopen; only a launch creates it.
- **R5** (`9536a2f`): `TryHold` locked in view mode without refusal or evidence. It refuses
  before it opens the file and keeps the evidence.
- **R6** (`b2cc7db`): the caller check of the bootstrap primitives saw only calls written
  where a primitive is named. It counts every reference: a function value, an argument, a
  dot import, a second import name, a variable inside the state package.
- **N1** (`55983a0`), not blocking: the two budgets of a build switch stated apart — two
  seconds of retries against shared holders, the writers' ten-second bound on each shared
  reacquisition.

The second round at `55983a0` closed R1–R5 and N1 and found R6 still open: a reference nested
in the receiver of a selector was skipped. `243dc4c` inspects every receiver with the same
recursive visitor, excluding only the selected name; a real outside file holding such a
reference fails the module check. `fefdd58` (N2, not blocking) moved the tests of the plan
into [stage3-state-tests.md](../v2/stage3-state-tests.md), so the plan stays under the
length limit.

The five checks pass on `fefdd58`; the workflow suite passed 107 of 107 at `55983a0`, the two
later commits changing only a test helper and documents. Part 1 was accepted on the Codex
side at `fefdd58`.

## Part 2: the run directory, the seam and the lease rule

- **The run directory** (`bb94944`, after the roadmap entry of part 1 in `aedb8bb`):
  `run/<name>.<epoch>/` made by the wrapper after the claim, handed to the adapter as
  `LaunchRequest.RunDir`, removed with the run, reclaimed after a kill once the run is proven
  dead ([stage3-rundir.md](../v2/stage3-rundir.md)).
- **Ordinary writes through the seam** (`70790cc`, `64003d5`, `64a16f4`, `a83e68e`): the
  plain primitives — `OpenFile`, `WriteFile`, `Link`, `Move`, `Chmod`, `Touch`, `Discard`,
  `RemoveAll`, `Flock` — then the registry's removals, the mailbox's in-place writes, links
  and retention touches, the control and receipt locks; `control.Prepare` now refuses a
  directory it did not make private instead of repairing it.
- **Guarded resources** (`fba3c58`, `bb8a98a`): the read clock's mapped word as
  `state.Counter`, whose load touches neither the filesystem nor a lock; sockets as
  `state.Listen`, whose close removes the path once, behind the guard, and whose failed
  chmod fails the bind.
- **Real leases in tests** (`a972ebc`): every test that writes a room holds a real lease;
  the worktree's records, outside the state, are written beside the seam.
- **`ErrNoLease`** (`1bb1e06`, `7c5508f`): one guard checks view mode on every path first,
  then that every path lies in a room this process holds the lease of; refusals are counted,
  so a swallowed one is still evidence. A static test over every production file and build
  variant fails on a write outside the seam not in its table; the seam tests run every
  primitive with and without the lease, every change form is shown to hold the lease through
  its last effect, and the adapters write nothing after `Close`.

Mutants: 12 for commit 4, 12 for commit 5, and for commit 6 every mutant of the guard, the
counter, the listener, the change scope and the adapters' close through `-overlay`, and five
of the static check written on disk, since its scanner reads sources from there — all
killed, the fixture's socket mutant by its test timing out in `Close`.

## Review of part 2: five findings

The review on the Codex side, at `7c5508f`, did not accept part 2. Main ran its seven probes,
each confirming its defect. The plan's length was met first: the run directory moved to
[stage3-rundir.md](../v2/stage3-rundir.md) (`efe001d`). The fixes, each with a regression
red before and green after:

- **R1** (`9d5b1a9`): a reply socket beside a socket the caller named outside the room was
  refused by the lease guard, and its receipts were lost. `state.ClaimSocket` gives the run
  authority over that one path — clearing a dead socket, binding, the close-time unlink —
  checked at each act against view mode and the room's lease, widening nothing inside the
  base.
- **R2** (`97ade13`): the run directory went in an ordinary deferred call, before the run's
  counted workers had stopped. It is now the run's last cleanup, run once they have, inside
  the run's hold on the lease; a worker stalled past the bounded stops leaves it, as the
  lease, to its own end or to a later launch's reclamation.
- **R3** (`c373ab4`): a failure between the adapter's plan and the start of its service —
  the record's update, the read clock — skipped the service's `Close`. Run owns the plan
  from the moment it is returned and closes its service once on every path out.
- **R4** (`a94eb53`): the static check missed a descriptor's `Chmod` and `Chown`, which
  work on a read-only descriptor, and excused a listen whose address merely contained a
  literal beginning with `@`. It counts every method of those names but a package's
  function, and excuses only an address proven abstract by its spelling; both shapes,
  written into real production files, fail the module check.
- **R5** (`c19efe4`): an authorization outlived its lock after a repeated `Authorize` or an
  `Unlock`. A lock is recorded once, and its authorization goes whenever it may hold
  nothing: `Close`, `Unlock`, a refused conversion, any failed take.
- **N1** (`cea4820`), not blocking: `flow.md` still said `list` deletes dead records, and a
  comment gave the free-lock name section to a view's cleanup.

Mutants: 22 through `-overlay`, each undoing one part of a fix — the claim's lease, path,
view, socket and room checks, the lane's and the launch's routing, the close-time unlink,
the plan's single close, the cleanup's order, the authorization's record and voiding, the
scanner's descriptor names and abstract address — each killed by the regression written
for it; the five on-disk mutants of commit 6 still fail the corrected module check.

The second round, on `68a8493`, closed R2, R3, R5 and N1 and kept two findings open, each
confirmed by a probe main ran:

- **R1** (`9474390`, `df920a2`): the claim took any path outside its own base for one
  outside every state, so a caller's socket in a room of another base was bound and cleared
  under the claiming room's lease. A claimed path below any base, or in a room of either

- **R4** (`84414a1`): the check took a selector on an import's name for that package's

- **N2** (`07c4b1c`), not blocking: the run directory's reclaim tests and their crash rig

Ten more mutants through `-overlay`, each undoing one part of these two fixes — the binding

## Part 3: the clearing of 1.x

- **The cleanup capability** (`01f2c34`, D6): `state.AuthorizeCleanup` scopes a launch's
  lease to the trees of 1.x beside the root of its own base and `v2/.clear.lock`, which a
  room's lease cannot rename, remove or lock; a tree's transitions are renames that never
  replace (`renameat2` with `RENAME_NOREPLACE`), each counting once the base's flush after it
  succeeded.
- **The clearing at a launch** (`5b446b3`): `internal/infra/legacy`, run by `build.Launch`
  right after the lease, from both launch routes. Admission over `rooms/` and every
  candidate (D1: a wrapper judged by `/proc` identity in the launch's own pid namespace, a
  missing process ended, a zombie not running, anything unreadable refusing); `rooms/` set
  aside under a drawn id; validation on the launch locks admission kept, checked at their
  renamed paths (D7), with a recreated `rooms/` refusing only on evidence; the counts
  recorded under `v2/` before the rename to validated, deletion only after it and its
  flush, a failed deletion deferred, a candidate that fails put back without replacing
  (D8); the marked counter of unread letters and undelivered reports, unknown where it
  cannot establish one (D9). The clear lock waits 10 s, each room 2 s, with no total beside,
  announced past the clear bound.
- **The rig and the matrices** (`753ef4f`): `test/upgraderig` runs a fault build with short
  bounds against a stand-in of 1.x whose sessions and commands are processes of their own.
  The crash matrix kills the clearing before each durable step a clean run of its world
  logged, then requires the launch after to refuse while a lasting condition is there and
  to clear otherwise; the concurrency matrix pauses it at each named step with a second
  launch beside it. The five checks run the worlds covering every pair of values (72 of 144
  crash worlds over 143 pairs, 74 of 530 concurrency worlds over 215 pairs); every world
  ran green before landing — 144 and 530, with 972 kill points — and every world keeps what
  lies beside the trees, hashed, and every room of a tree not validated its letter.
- **The decisions held** (`8e4d46b`): a mutant of each decision of the clearing — 41, over
  D1, D6–D9 and the bounds — is killed; five that survived a first pass got the tests that
  kill them: a room gone from the tree set aside, a taken candidate name drawn again, the
  read under the clear lock, a room's wait, an unlistable mailbox.
- **The live gate** (main, on `8e4d46b`): against the installed 1.0.3 with a stub harness, a
  refusal with exit 1 naming the live session while it ran and its mail kept, then after it
  ended the clearing, a truthful summary and a normal start under `v2/`, unrelated files
  untouched; a SIGKILLed 1.x wrapper admitted as ended and its unread letter counted. A
  refused launch leaves the root its lease made; that is the order the protocol sets, and
  the documents now say so. Recorded with the timing pass in
  [stage3-s17-evidence.md](../v2/stage3-s17-evidence.md) (`804ba46`): the hash of the
  8.6 MB release build costs a median of 2.76 ms warm and 4.02 ms cold, and adds about 2 ms to the median of
  `rewake pending` warm and 3 ms with its pages advised away; part 1's directory flushes cost
  13 µs at a launch.

## Review of part 3: four findings and two gaps

The Codex side reviewed `c1c2f5b..6d4f79c` and did not accept it: four findings in the
code, confirmed by probes main ran, and two gaps in the evidence. It accepted the timing
gate as meeting the adopted method, the skeleton a refused launch leaves, the orphaned
count file and the refusal of a 1.x record without a pid namespace. Each confirmed probe is
now a permanent regression, red on `6d4f79c` and green after.

- **R1, high — a validated name deleted without its flush established** (`b436777`). A
  launch waiting behind a clearer whose flush of the validated rename failed found the
  name and deleted the tree; its own bootstrap flush came before that rename and vouched
  for nothing. A clearing now settles the base (`Cleanup.Settle`) before deleting a
  validated tree it finds, and refuses, deleting nothing, when it cannot:
  `TestAValidatedTreeIsDeletedOnlyOnceSettled`.
- **R2 — a completed deletion hidden by a later failure** (`b436777`). A validated tree
  removed and then a failed set-aside left stderr silent and a refusal saying nothing was
  removed; the rig's oracle shared the wrong message. What an invocation removed or
  deferred is now said on every return after admission, and each refusal names the tree it
  failed on: `TestEveryOutcomeIsSaidBesideALaterRefusal`; the oracle expects the summary
  beside every refusal.
- **R3 — incomplete recorded counts printed as zeros** (`b436777`). `{}` and `null` read as
  three exact zeros. Counts are read field by field, a count absent, null or not a whole
  number from zero unknown: new cases of `TestLegacySummarySurvivesPartialDeletion`.
- **R4 — a FIFO at a session record held admission** (`6d4148d`) until a writer came, the
  clear lock and room locks with it. Every file the clearing opens — record, letter, 1.x
  lock, clear lock — must be a regular file, refused before a non-waiting open and checked
  on the descriptor: `TestASpecialFileIsRefusedWithoutWaiting`.
- **G2 — no world of unreadable process data in the rig** (`a934db5`). A fault build reads
  a `/proc`-shaped tree of the test's through `REWAKE_FAULT_PROC`; the old-state dimension
  gains a wrapper whose stat cannot be read and one whose stat does not parse, crossed
  with the trees and one or two launches, each refused with its mail kept and cleared once
  the machine's `/proc` is read again. The pairwise run now has 80 of 160 crash worlds over
  157 pairs and 82 of 590 concurrency worlds over 235; the full matrix ran all 750 worlds
  and 1,102 kill points green.
- **N1** (`a934db5`): the reread test holds the second launch at a new named step,
  `legacy found`, between its first read and the clear lock, instead of sleeping.
- **N2** (`e654f0d`): `docs/session-record.md` no longer says a listing or a lookup
  deletes dead records; views never prune, and only a change form does, under its lease.
- **G1 — the live gate with unrelated files and real worktree storage** is main's: a rerun
  on the fixed candidate with non-empty files beside `rooms/`, in work and home, and a
  real 1.x worktree session, recorded as a new entry of the evidence.

A mutant of each fix — 17, over R1–R4, G2 and N1 — is killed.

## Open

  side; then S17 lands on `v2` as one step.
- Stated limits of part 3: a crash between a tree's deletion and the removal of its counts
  leaves that small file under `v2/`, which nothing reads again; the clearing assumes the
  launch sees the pid namespace the 1.x sessions ran in and refuses a record of another one

  the check and the act is not seen; the adapters of stage 3 do not use the run directory

  same-named local in a file with a dot import counts as a reference, the safe side; a
  worker that never returns holds the lease until the process exits, on purpose.
