## The inventory

Taken with `go/types` before any commit, over the four build variants with tests: every
reference to and from a declaration of `cli`, the closure of each of `cli`'s 336 tests,
the top-level names of `core/mail` and `cli` for collisions, the mutations resolved and
checked against their files, and `git grep` for text. A compile of the moving code inside
`core/mail` was tried on a scratch tree first. What the step expected, and what it found:

- **The logic takes core values.** Confirmed: the moving code reaches nothing in `cli`
  outside itself and no package `core/mail` does not already import.
- **The plan's names.** Partly stale: `hookLockWait` has been `turnEndLockWait` since S9,
  `printHold` left with the hook command, and `liveSenders` and `joinTurnText` sit in
  `turn_hold.go`, not `turn_reports.go`.
- **The test seam.** `beforeReports` has more setters than the plan named — twelve places
  in five test files.
- **No test names an unexported identifier that moves.** Refuted: the helper `endTurn`
  calls the end, and `TestAnAttemptNotProvenInItsTurnIsMarkUnproven` calls `judgeMark`
  with the verdict's constants. Both stay in `cli`, naming the exported names.
- **The string consumers.** The seven mutations of `turn_reports.go`, `turn_hold.go` and
  `turnended.go`, as counted, with texts that name nothing the move renames; and one more
  the plan did not list, `end-thread-ignored`, which edits `cli/completion.go` and quotes
  its two calls into the end.
- **S15.** The turn-end reports call `ReportThreadChanged`, a function of the delivery
  server's file group, so S15 has to keep it on the mail side.

  calls, and no test changed. Every setter assigns the variable before the end that should
