# The help told true

September 28, 2026. Found by review-claude, which checked every help page, the guide,
the refusals and the briefings of 1fd9e8b against the code and against live calls in a
private state directory; fixed the same day, before 1.0.0, since the help is the
contract an agent builds its calls from.

## What was found

- **High: `inbox --awaited` knew two outcomes of an ended recipient, the code three.**
  The help said an ended recipient means no report is coming; the code prints
  "<name> ended; a resume of <name> in its conversation may still report" for a day
  from the read, and main's playbook warns against sending such a task again.
- **High: a grant's end was told wrong or not at all.** `send --help` said a grant is
  taken back once the task is reported on; on Codex it goes at the next delivery after
  the report, and a person's own turn drops it at once. What a stopped turn, a pending
  mark, an error or a withdrawal does to it, the Claude Code modes in which it lives to
  the session's end, and the conditions of a restore after a cold resume were in the
  documents only.
- **High: `--grant-git` to a Claude Code session was refused although the roles and the
  help promised it,** with exit 2 and no way on, while the same refusal for a directory
  was exit 1.
- **High: the documents told main to launch writers,** which a session cannot: the
  nested launch refusal was in no help page and in no playbook.
- **High: `send --wait` above 5 for a task or a heads-up waited 5** and said it had
  waited the whole time; the help's own example asked for 20.
- **High: `rewake send <name> -h` sent a task reading "-h".**
- **Medium:** `/home` and `/mnt` given as broad examples that can never be granted; the
  `--main` summary saying main requests permission to commit, which nothing does;
  `rewake claude --worktree fix-login` making a checkout of a generated name with the
  word as the prompt, where Claude Code's own flag would take it as the name; a typed
  `--worktree` beside an alias's refused as given twice on Claude Code; "passed
  untouched, with one exception" where there are several; `pending --help` missing a
  refusal and the Stop hook's hold; no refusal of a send to oneself; flags checked only
  after the session lookup; stale lines in `flow.md`, `flow-endings.md` and `roles.md`.
- **Low:** the telemetry paragraph repeated in the send and inbox help, the interrupt
  help missing its answer wait, the plain shell's compact refusal naming no way on, and
  "--grant-dir-broad --grant-dir-broad" in a refusal.

## What was done

- Grants: `send --help` says the task is open through a stopped or pending turn and
  settled by the report, an error or a withdrawal; when Codex and Claude Code take a
  grant back, per mode; and that a restore after a cold resume needs the main that
  granted still running, the same conversation and a day at most. The executor
  playbook says the grant holds through a stopped or pending turn; main's says a
  restart of main forfeits every restore. The broad examples name a drive such as
  `/mnt/d` and a live session's directory, main's own checkout included.
- `inbox --awaited` names the third outcome with its day.
- `--grant-git` is for a Codex write session: said in the flag, the `--write` summary,
  the write and main playbooks, `flow.md` and `git-grants.md`. A recipient whose harness
  cannot take it is refused with exit 1 — the call is right, the target cannot carry it
  out, as for `--grant-dir` — and a recipient whose role cannot is refused with exit 2,
  a wrong call as a question to a silent role is; both name the way on.
- The `--main` summary says what main does: it alone grants, and rewake adds it no
  permission.
- The nested launch rule is on every launch page and in main's playbook; `launch.md`
  says the owner starts each writer in its worktree, and `flow.md` says so before
  Act 1.
- The launch notes list what does not pass as written: a first `--help`, rewake's
  `--worktree`, an alias's flag replaced, and on Codex the refused server and
  configuration flags; the Claude Code note lists every continuation refused beside
  `--worktree`.
- `--wait` is the delivery's whole wait for a task or a heads-up, and a question gives
  its delivery 5 of it at most. Chosen over stating a cap: it is the smaller change,
  one branch in `reportSent`, and makes the flag and its example mean what they say.
  `edit` shares the code and checks `--wait` before any lookup as well.
- `-h` is `--help` on every command, and before the command word; any other short flag
  before `--` is refused, and a text beginning with a dash goes after `--`.
- `send` checks the kind and `--wait` before the session lookup, and refuses a session
  naming itself with exit 2.
- `rewake claude --worktree <word>` is refused with `--worktree=<word>` and
  `--worktree -- <word>` as the ways on; Codex keeps the word as its prompt, as its own
  switch does. `--worktree` is a single-use switch of Claude Code, as of Codex, so a
  typed one replaces an alias's.
- `pending --help` names the fourth refusal and the hold; `interrupt --help` its answer
  wait; the plain shell's compact and interrupt refusal says to run it from main or ask
  main; the telemetry paragraph stays on `list` alone; the doubled flag is gone.
- The guide says a grant of either kind goes only with the task or question carrying it;
  `flow.md` gives the Claude Code grant path, the intro as the whole playbook and the
  exceptions of the command line; `flow-endings.md` Act 8 names the resume and its
  grant, and the compaction row its real waits; the roles table says what each role's
  playbook says.

## Review

review-codex checked the change on a built binary in a private state directory and
confirmed four findings, fixed the same day:

- **P2:** the help promised every grant back after the report, but the Git metadata of
  a Codex worker's own checkout, opened by `--grant-git` alone, is not journaled and
  stays for the rest of the thread. The Codex note now limits the take-back to
  directory grants and what came with them, a note of its own says the standalone
  `--grant-git` is never taken back, and main's playbook and `flow.md` say so.
- **P2:** a long `--wait` kept waiting for a recipient that had ended: liveness was
  asked only after the wait, so `--wait=3600` could mean an hour where it used to be
  5 s at most. `inbox.Await` now asks every half second whether the run still holds
  its name and ends the wait when it does not; a run in another pid namespace still
  counts as running, as everywhere else.
- **P2:** `-h` before the command word returned at once: `-h send` printed the guide and
  `-h --bogus` exited 0. It is now read exactly as `--help`, with the same checks after.
- **P3:** `rewake edit` could re-send an old task to oneself; it now refuses with exit 2
  and names `rewake withdraw`, which stays allowed.

## What stays open

- Switches taking values inconsistently (`--notify=false`, `--peek=`,
  `worktree land --into=`), and no time limit on git calls: out of this round.
