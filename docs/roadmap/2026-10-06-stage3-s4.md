# Stage 3 of 2.0: S4 built and accepted

S4 is the fourth step of stage 3 ([stage3.md](../v2/stage3.md)): the turn-end and read
code takes only core-owned inputs, in place, so that S14 can move it to `core/mail` as a
rename ([stage3-steps.md](../v2/stage3-steps.md#s4-core-owned-turn-end-and-read-inputs)).
It was built and accepted on October 6, 2026, in five commits and one review round. No
behaviour changed, and the step needed no Codex-side acceptance.

## The five commits

1. `c89057a`: a failed turn end names its report kind by `inbox.Error`, not by the send
   command's error kind.
2. `8a0807e`: the payload decoder of the hook and the notify, `completedTurn`, moves to
   `cli/turn_payload.go` and keeps the two payload-only fields, the thread and the hold.
   The hold becomes an argument of the end. Pending is decided from the mark alone.
3. `2f33a31`: a pending mark is judged by `inbox.AttemptScope` and the turn's latest
   start. The pending command reads that start under the mailbox lock, so `judgeMark`
   no longer reads the command's context or the telemetry file. The layout table's
   exception for `pending_turn.go` importing telemetry is retired.
4. `396f11c`: a read is acknowledged by `inbox.ReadEvidence` and `inbox.EndGate`.
   `AcknowledgeRead` stays as the shim that converts the tool's exposure. Letters are
   marked by the run, through `markWhole`, rather than by the read site.
5. `8663fcc`: the neutral value of a turn end is `inbox.TurnEnd` with `Kind()`.
   `ReportCompletion` converts the adapter's completion to it. The kind strings and
   the operation's name are unchanged.

## The evidence

- **Test outcomes**: 5345 per tree, 5168 passing and 177 skipped. The set of (package,
  test, outcome) was identical on `b24dcad` and after each commit. Only the number of a
  temporary directory in nine subtest names was normalized.
- **Record bytes**: the existing record-shape and golden tests are among those outcomes.
  A probe added through a test overlay also ran on each tree and stayed equal to the
  base. It covered the operation hashes raw, the decoder's output, and the records of
  the end, the hold and the read. The review set the limit of that claim: those records
  are compared as normalized dumps, so the rest of the argument is the unchanged record
  construction, compared directly in the diff.
- **Mutation strings**: all 96 of the workflow suite's still match exactly once on
  every tree. In commit 2 two of them changed their text, after the hold became a
  parameter and pending a local. Two more changed their path to `cli/turn_payload.go`,
  which the step's list had not named. The review found both changes necessary and
  correct.
- **The workflow suite after commit 5**: 163 cases, 160 passing and the same three
  unsupported, identical case by case to S3's run. The four controls whose mutations
  changed ran and passed.
- **The inventory**, retaken with `go/types`: no dependency outside S14's table. The
  only outstanding `cli` dependency is the test seam `beforeReports`, already S14's
  preparatory commit.

## The review

One round, **PASS on all five commits**, with no blocking finding. It agreed to three
corrections of S14's inventory, applied in
[stage3-moves.md](../v2/stage3-moves.md#s14-the-turn-end-and-read-code-to-coremail) and
[stage3-packages.md](../v2/stage3-packages.md):

- `acknowledgeRead` moves with the read's acknowledgment;
- the two former `turn_result.go` mutations stay with the decoder in `cli`;
- `attemptScope` stays in `cli` beside `inOwnTurn`.
