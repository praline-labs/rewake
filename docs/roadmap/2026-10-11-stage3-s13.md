# Stage 3 of 2.0: S13 accepted

S13 is the thirteenth step of stage 3 ([stage3.md](../archive/v2/stage3.md)): the `core` moves
([stage3-moves.md](../archive/v2/stage3-moves.md#s13-core-moves), the places from
[stage3-packages.md](../archive/v2/stage3-packages.md)). It was built on October 11, 2026, on
branch `s3-s13` from `b99358b`: four preparatory commits in place, a correction of the
plans, the move, two fixes of what the move missed, and this entry. The step needs no
acceptance on the Codex side; it was accepted in review the same day.

## The inventory

Taken with `go/types` before any commit, over the four build variants with tests, with
`go list -test` for each test's imports and `git grep` for text. What the step expected,
and what it found:

- **`inbox` imports only `core` and `infra`.** Confirmed: the standard library,
  `boottime`, `buildtime`, `state`, `receipt`, `registry`, `role` and `sessionstate`; its
  tests add `proc` and `registrytest`. No package of the twelve imports an adapter,
  `bridge`, `wrap` or `cli`, and the closure of every test of theirs stays inside the
  twelve, `infra` and the standard library, so each test moves with its package.
- **The string consumers.** The counts were stale. The mutations name `inbox` 13 times
  and `grantauth` 3 times; `control` and `grant` have had none since the columns of S8
  and S9 left. The `-X` values name `inbox` as a bare `"inbox"` that `buildValue` joins
  to a path, so a search for paths does not find it. Beside them: twelve transition
  entries, five name-exception keys, the tree of [code.md](../code.md), 204 test paths in
  [rules/](../rules/README.md), and 37 living documents with paths or qualified names.
- **The delivery server's files.** All ten the plan names exist, and an eleventh,
  `settle_recorded.go`, newer than the inventory at `b6ed4ed`, belongs with them.

## The preparatory commits

Each changes no behaviour, and each was shown not to:

- **The test of the lossy waiters' callers** (`b4f6e70`) found the module as `../..`
  and the package by the word `inbox`; moved and renamed, it would have passed on
  nothing. It now walks up to `go.mod`, knows the package by its directory and import
  path under whatever name a file imports it, and fails when it has read none of either.
  A call put in `cli` and one in the package itself each fail it, before the move and
  after.
- **The failure table's test** (`c15d91a`) read `../wrap`, which would have yielded no
  files after the move and dropped the wrapper's tests silently. It names
  `internal/wrap` from the module root and fails on a directory without tests.
- **The 2.0 names** (`b55e027`): every importer imports `inbox`, `sessionstate`,
  `grantauth` and `grantauthtest` as `mail`, `session`, `authority` and `authoritytest`,
  by a tool over `go/types`; the locals those names would shadow in eight files are
  renamed; seven comments and four mutations' texts follow. `cmd/rewake`, stripped and
  without a build id, is byte for byte the same before and after, plain and with the
  fixture; of the test binaries, only those of the six tests whose locals were renamed
  differ, in stack offsets, which the compiler orders by name, and the suite's in its
  mutations' texts.
- **The file group** (`51af119`): the layout test records the delivery server's eleven
  files as a group bound for `host/delivery` in S15. It changes no rule — the files are
  judged by `core`'s like the rest of the package — and fails once a file it names is

Then `cab4ddd` corrects the plans to what the inventory found: S13's counts and the

## The move

`070ffb4`: `git mv` of the ten directories, the two test helpers inside theirs, to
`internal/core`; the package clauses `session`, `authority`, `authoritytest`, `mail` and
`mail_test`; the import paths, with the aliases the preparatory commit added dropped and
the import blocks sorted again; the twelve transition entries out, the five name keys,
the file group's key, the two `-X` values, the sixteen mutations' files, the tree of
[code.md](../code.md) realigned to its longest line, the test paths of
[rules/](../rules/README.md), and the paths and qualified names of the living documents,
`AGENTS.md` among them. All 210 files pair as renames at 89–100% similarity, 166 of
them at 99% or more. The dated records of the roadmap and the reviews, and the plans of
[v2/](../v2/README.md), keep the paths they were written against.

Before it, the inventory's literal scan was rerun on the preparatory tree, and what it
cannot see was looked for by hand: relative paths in the moving packages (only `brief`'s
`testdata`, which moves with it), paths built by a format or concatenation (only
`buildValue`), package paths computed at run time (none), paths in scripts and
configuration (none), and Go source quoted inside strings (the mutations' texts, checked
by a tool that requires each to occur once in its file, as the suite does).

Two fixes followed before review. `3323570` renames the block comment of `inbox.go`,
`Package inbox`, which the move's rewrite of package comments missed and golangci-lint
found. That comment names a harness, so its name exception's sum, taken over the
comment's text, changes with it: `48f7bb4` records the new sum, the count staying one.

## Review: accepted

One round, no code defect. The review compared the preparatory import commit token by
token: 156 files differ only by the aliases, qualifiers, comments and the four mutation
texts, the other eight by the renamed locals, none of which captures another name or
changes a value; built from clean snapshots without paths or build identity, `cmd/rewake`
before and after it is byte for byte the same, plain and with the fixture. On the moved
tree, the two tests that now find the module by `go.mod` were shown to fail on a caller
outside `internal/` under another alias, on a caller inside the package and on a missing
test of `internal/wrap`, so they do not pass on nothing. The file group was confirmed
record-only: no import rule reads it. The move itself matched token for token in 434 of
its 436 Go files after the path, package and import changes; the other two are the twelve
transition entries leaving and the one exception sum. The 89–100% similarity holds for
the move measured from the plans' commit; measured from the step's base, with the
preparatory commits, the renamed files sit at 60–100%.
